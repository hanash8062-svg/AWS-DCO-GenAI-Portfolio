## 1. 내가 읽은 교육용 샘플 SOP 제목

SAMPLE-DCO-SOP-04: 샘플 Link Down 이벤트 기록 및 전달 절차

---

## 2. SOP의 목적

내가 이해한 목적:

이 SOP의 목적은 교육용 샘플 로그에서 Link Down 이벤트가 관찰되었을 때, 학생이 해당 상황을 바로 장애 원인으로 단정하지 않고 발생 시간, 대상 장비, 반복 여부, Ticket 상태, Escalation 필요 여부를 순서대로 정리하는 연습을 하기 위한 것이다.

DCO 직무 이해 관점에서 보면, SOP는 단순히 “무엇을 해야 하는지”를 적은 문서가 아니라, 반복되는 상황에서 확인 기준을 표준화하고 작업자마다 다른 방식으로 판단하는 것을 줄이기 위한 절차 문서라고 이해했다.

특히 Link Down과 같은 네트워크 이벤트는 원인을 바로 확정하기보다, 로그에 나타난 관찰 사실을 먼저 정리하는 것이 중요하다. 따라서 이 SOP는 이벤트 확인, 기록, 전달, 보고서 초안 작성까지 이어지는 기본 흐름을 익히기 위한 학습용 문서라고 볼 수 있다.

---

## 3. SOP 절차 요약

1. 샘플 로그에서 Link Down 이벤트가 발생한 시간을 확인한다.
   이벤트 타임스탬프를 먼저 확인해야 이후 반복 여부나 다른 이벤트와의 시간 관계를 정리할 수 있다.

2. 이벤트에 표시된 샘플 장비명을 확인한다.
   어떤 Rack, Server, Switch, NIC 등과 관련된 이벤트인지 구분하기 위해 대상 장비 정보를 정리한다.

3. 동일한 샘플 장비에서 Link Down 이벤트가 반복되었는지 확인한다.
   단발성 이벤트인지, 동일 대상에서 반복적으로 발생한 이벤트인지 구분하는 것은 Ticket 기록과 Escalation 판단에 중요하다.

4. Ticket opened 또는 Ticket escalated 표현이 함께 있는지 확인한다.
   이미 Ticket이 생성되었는지, 상위 단계로 전달된 상태인지 확인하면 현재 이벤트의 처리 상태를 파악하는 데 도움이 된다.

5. 영향 범위는 단정하지 않고 로그에 나타난 관찰 내용만 정리한다.
   예를 들어 “서비스 전체 장애”라고 쓰기보다는, “샘플 로그에서 특정 장비의 Link Down 이벤트가 관찰됨”처럼 확인된 사실 중심으로 표현한다.

6. 혼자 판단하기 어려운 내용은 Escalation 필요 여부로 표시한다.
   원인 판단, 영향 범위 판단, 후속 조치 판단이 어려운 경우에는 혼자 결론을 내리지 않고 전달 필요 여부를 구분한다.

7. 확인한 내용을 Handover Memo 또는 Incident Report 초안에 넣을 수 있도록 짧고 구조적으로 정리한다.
   발생 시간, 대상 장비, 반복 여부, Ticket 상태, Escalation 필요 여부를 중심으로 후속 담당자가 이해하기 쉽게 남긴다.

---

## 4. 주의사항

* 이 SOP는 실제 AWS 내부 SOP가 아니라 교육용 샘플 SOP이다.
* 실제 장비에 접속하지 않는다.
* 실제 네트워크 진단 명령을 실행하지 않는다.
* 실제 AWS 환경에 접속하지 않는다.
* 실제 IP 주소, 실제 티켓 번호, 실제 장비 시리얼을 사용하지 않는다.
* Link Down의 원인을 케이블, 포트, 스위치, 서버 문제 중 하나로 바로 단정하지 않는다.
* 로그에 나타난 관찰 내용과 내가 추정한 내용을 구분해서 작성한다.
* Ticket 상태와 Escalation 여부는 확인된 표현을 기준으로 정리한다.
* Handover Memo나 Incident Report 초안에는 다음 사람이 이어서 볼 수 있도록 짧고 명확하게 작성한다.

내가 추가로 주의해야 한다고 생각한 점:

SOP를 읽을 때 절차를 단순히 외우기보다, 각 단계가 왜 필요한지 이해하는 것이 중요하다고 생각했다.
특히 Link Down 같은 표현은 네트워크 연결 상태와 관련된 이벤트이지만, 그 자체만으로 원인이나 영향 범위를 확정할 수는 없다.
따라서 DCO 직무 이해 맥락에서는 “확인한 사실”, “추가 확인이 필요한 부분”, “전달이 필요한 부분”을 구분해서 기록하는 태도가 중요하다고 느꼈다.

## 5. 확인항목

□ Link Down 이벤트의 발생 시간을 확인했습니다.
□ 이벤트에 표시된 샘플 장비명을 확인했습니다.
□ 동일 장비에서 반복 이벤트가 있었는지 확인했습니다.
□ Ticket opened 또는 Ticket escalated 표현이 있는지 확인했습니다.
□ 영향 범위를 단정하지 않고 관찰 내용 중심으로 정리했습니다.
□ Escalation 필요 여부를 표시했습니다.
□ Handover Memo 또는 Incident Report 초안에 넣을 수 있도록 핵심 정보를 정리했습니다.
□ 실제 장비명, 실제 티켓 번호, 실제 IP 주소, 실제 장비 시리얼을 사용하지 않았습니다.

## 6. 내가 만든 SOP 체크리스트

□ 1단계: 샘플 로그에서 Link Down 이벤트가 표시된 시간을 확인한다.

□ 2단계: 이벤트와 연결된 샘플 장비명을 확인한다.
예: SAMPLE-RACK, DEMO-SERVER, EDU-SWITCH와 같은 교육용 장비명만 사용한다.

□ 3단계: 동일 장비에서 Link Down 이벤트가 반복적으로 발생했는지 확인한다.
단발성 이벤트인지, 반복 이벤트인지 구분한다.

□ 4단계: Ticket opened 또는 Ticket escalated 표현이 함께 있는지 확인한다.
이미 Ticket이 생성되었는지, Escalation 상태인지 구분한다.

□ 5단계: 로그에 나타난 관찰 사실만 정리한다.
원인, 영향 범위, 장애 수준은 확인된 내용이 아니면 단정하지 않는다.

□ 6단계: 혼자 판단하기 어려운 내용은 Escalation 필요 여부로 표시한다.
추가 판단이 필요한 부분은 “추가 확인 필요” 또는 “Escalation 검토 필요”로 남긴다.

□ 7단계: Handover Memo에 남길 핵심 정보를 정리한다.
발생 시간, 샘플 장비명, 반복 여부, Ticket 상태, Escalation 필요 여부를 간단히 남긴다.

□ 8단계: Incident Report 초안에 활용할 수 있도록 사건 흐름을 짧게 요약한다.
“언제, 어떤 샘플 장비에서, 어떤 이벤트가 관찰되었고, 어떤 확인이 필요했는지” 중심으로 작성한다.
